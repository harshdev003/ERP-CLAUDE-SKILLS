# Notion target — schema reference

## Target database

- **Workspace:** aurahealth
- **Database:** Growth Readings
- **Database ID:** `2aa75e23af20801ebfbcf40645cb7469`
- **Data source ID:** `2aa75e23-af20-8020-8ec4-000bd69ced6d` (under the database; the create script passes this as the page parent)
- **URL:** https://www.notion.so/2aa75e23af20801ebfbcf40645cb7469

The skill **always discovers the schema at runtime** via REST (`GET /data_sources/<id>`,
falling back to resolving the data source from the database id) — don't hardcode
property names. Notion's UI lets the DB owner rename properties freely, and this
skill must keep working after a rename.

> **Access:** the marketing Growth Readings DB lives outside the AI Knowledge
> teamspace, so the `Aura AI Knowledge` integration behind `NOTION_TOKEN` must be
> connected to it (DB → `···` → Connections → `Aura AI Knowledge`). Without the
> connection every REST call 404s with `object_not_found`.

## Current schema (as of 2026-04-24)

| Property | Type | Role |
|---|---|---|
| `Title` | title | Video title |
| `Source` | text | YouTube URL (stored as plain text) |
| `Date Published` | date | Fill with today's date (or video publish date) — use expanded key `date:Date Published:start` with an ISO-8601 date |
| `Reviewed` | select (options: `Yes`) | Leave empty on creation; a human sets this after reading |

## Property mapping (degrade gracefully if renamed)

| Canonical field | Likely property names (in order of preference) |
|---|---|
| Title | `Title`, `Name`, `Video`, `Video Title` |
| Source URL | `Source`, `URL`, `Link`, `YouTube`, `YouTube URL` |
| Date | `Date Published`, `Date`, `Added`, `Date Added`, `Published` |

If a canonical field has no matching property:

- **Title missing** → this is an error (every Notion DB has a title property); surface it and stop.
- **Source missing** → add the URL as the first paragraph of the page body instead, and warn the user.
- **Date missing** → skip silently.

## Page body structure

Always write the comprehensive summary into the page body (not a rich-text
property), in this block order:

```
heading_2: "Overview"
paragraph: <2-3 sentence TL;DR>

heading_2: "Key Points"
bulleted_list_item × N

heading_2: "Detailed Timeline"
paragraph × N (bold timestamps at the start of each paragraph)

heading_2: "Notable Quotes"
quote × N

heading_2: "Takeaways & Action Items"
bulleted_list_item × N

heading_2: "Further Watching"         ← only if populated
bulleted_list_item × N                 ← only if populated

divider

callout: "🤖 Generated by summarize-youtube-to-notion skill on YYYY-MM-DD"
```

## Notion REST call shape

The skill creates pages via the REST API — **no MCP**. [`scripts/file_to_notion.py`](../scripts/file_to_notion.py)
discovers the schema, converts the Markdown body to block JSON via
[`scripts/notion_blocks.py`](../scripts/notion_blocks.py), and issues `POST /pages`.
The request body it builds:

```json
{
  "parent": { "type": "data_source_id", "data_source_id": "2aa75e23-af20-8020-8ec4-000bd69ced6d" },
  "icon": { "type": "emoji", "emoji": "🎧" },
  "properties": {
    "title": { "title": [{ "type": "text", "text": { "content": "<video title>" } }] },
    "Source": { "rich_text": [{ "type": "text", "text": { "content": "https://www.youtube.com/watch?v=..." } }] },
    "Date Published": { "date": { "start": "2026-04-24" } }
  },
  "children": [ /* up to 100 Notion blocks from notion_blocks.markdown_to_blocks() */ ]
}
```

Key points:

- **Parent is `data_source_id`, not `database_id`.** The script resolves the live
  data source id at runtime (`GET /data_sources/<id>`, falling back to the database
  id) so a renamed/re-pointed data source keeps working.
- **The title is keyed by the literal `title` id, lowercase** — required under Notion
  API `2025-09-03` when the parent is a `data_source_id` (display-name keys are
  rejected on create). Other properties are keyed by their discovered display name.
- **`Source` value shape follows its property type** — `{"url": …}` if the property
  is a URL type, `{"rich_text": …}` if it's text (the script checks the schema).
- **Body is block JSON, not Markdown.** `notion_blocks.markdown_to_blocks()` maps
  `##` → heading_2, `-` → bulleted_list_item, `>` → quote, `---` → divider, and
  inline `**bold**` / `*italic*` / `` `code` `` / `[links](url)`. Blocks past the
  100-per-request cap are appended via `PATCH /blocks/<page>/children`.
- **Leave `Reviewed` unset on creation** — it's a human review flag.

## Idempotency

This skill is **not idempotent** — running it twice on the same URL creates two
pages. If you want dedupe, add a REST query before Step 5 filtering the data source
on the Source URL (`notion.query_data_source(ds_id, filter={"property": "Source",
"rich_text": {"equals": "<canonical url>"}})`) and decide per-call whether to skip,
update, or create anyway.
