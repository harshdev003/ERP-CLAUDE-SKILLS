# youtube-transcript-api — usage + edge cases

The `scripts/fetch_transcript.py` script uses [`youtube-transcript-api`](https://github.com/jdepoix/youtube-transcript-api)
to pull captions directly from YouTube. No API key. No account. Completely free.

## Why this library

YouTube serves captions for almost every public video — either creator-uploaded
or auto-generated by YouTube's own speech recognition. This library scrapes
them through the same public interface YouTube's own embedded player uses.

Alternatives considered and rejected:

- **YouTube Data API v3** — requires a Google Cloud project, has strict daily
  quotas, and explicitly *does not* return the caption text for videos you
  don't own.
- **Consumer summarization wrappers** (Glasp, TubeChat, and similar) — no
  stable developer APIs; most require signup, scraping, or captcha flows.
- **yt-dlp `--write-auto-subs`** — works, but spawning a CLI and parsing VTT
  files is heavier than the pip-installable Python library.

## Version this script targets

`youtube-transcript-api >= 1.0` (class-based API with `.list()` and `.fetch()`
instance methods). If you see `AttributeError: type object 'YouTubeTranscriptApi'
has no attribute 'list_transcripts'`, the installed version is too old — the
pre-1.0 API used classmethods and has been removed.

Install / upgrade:

```sh
python3 -m pip install --user --break-system-packages --upgrade youtube-transcript-api
```

## API cheat sheet

```python
from youtube_transcript_api import YouTubeTranscriptApi

yt = YouTubeTranscriptApi()

# 1. List available transcripts for a video
transcript_list = yt.list(video_id)

# 2. Pick the best transcript
#    find_manually_created_transcript and find_generated_transcript raise on miss
picked = transcript_list.find_generated_transcript(["en", "en-US", "en-GB"])

# 3. Translate if needed (not all are translatable)
if picked.language_code != "en" and picked.is_translatable:
    picked = picked.translate("en")

# 4. Fetch the snippets
fetched = picked.fetch()  # iterable of FetchedTranscriptSnippet

for snip in fetched:
    print(snip.start, snip.duration, snip.text)
```

Each `FetchedTranscriptSnippet` has `.text`, `.start` (seconds, float), and
`.duration` (seconds, float).

## Fallback order the script uses

The script tries these in order and stops at the first hit:

1. Manually created transcript in English (`en`, `en-US`, `en-GB`)
2. Any manually created transcript → auto-translate to English if translatable
3. Auto-generated transcript in English
4. Any auto-generated transcript → auto-translate to English if translatable

This handles the common cases cleanly:

- English video with auto-captions → #3
- Spanish interview with manual English subs → #1 (finds English directly)
- Korean interview with auto-translated English → #4 (picks Korean auto,
  translates)
- Arabic video with no English anywhere → falls through to #4, picks Arabic
  auto, translates — surfaces the `auto_translated_to_english` soft error so
  Claude can flag the summary as "translated transcript"

## Edge cases and how the script handles them

| Situation | Behavior |
|---|---|
| Captions disabled on the video | `TranscriptsDisabled` → output has `transcript:transcripts_disabled_on_video` in `errors`, empty `transcript` list |
| Video private / age-restricted / removed | `VideoUnavailable` or oEmbed 401 → output has `transcript:video_unavailable` or `oembed:private_or_restricted` in `errors` |
| Video exists but no caption in any language | Transcript list is empty → `transcript:no_transcript_available` in `errors` |
| Auto-translated English used | Soft error `transcript:auto_translated_to_english` in `errors` (not a failure) |
| Very long videos (>2 hr) | Works fine — script iterates the full snippet list; large outputs may exceed Claude's context, in which case Claude should chunk the transcript before summarizing |
| Livestreams / premieres (not yet ended) | Usually no transcript available yet — same as "captions disabled" |

## Rate limiting

YouTube does throttle if you hammer the endpoint. For batches of >10 URLs:

- Add `time.sleep(2)` between calls in a wrapping script
- On a 429-like failure, back off and retry once
- For large batches, prefer doing them serially overnight rather than parallelizing

## If this stops working

The library occasionally breaks when YouTube changes its internal API (usually
within a week or two of the breakage). Fixes:

1. Upgrade: `pip install --upgrade youtube-transcript-api`
2. Check [GitHub Issues](https://github.com/jdepoix/youtube-transcript-api/issues)
3. As an emergency fallback, switch to `yt-dlp`:
   ```sh
   yt-dlp --write-auto-subs --sub-lang en --skip-download \
          --sub-format vtt -o '%(id)s' "<url>"
   ```
   Then parse the VTT file. Add a `scripts/ytdlp_fallback.py` if this becomes
   a recurring need.
