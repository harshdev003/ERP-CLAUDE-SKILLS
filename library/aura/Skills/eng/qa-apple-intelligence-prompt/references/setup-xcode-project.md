# Setting up `ApplePromptTesterIOS.xcodeproj` (one-time)

The `qa-apple-intelligence-prompt` skill drives an Xcode project; it
does not generate one. This walkthrough creates the project once at
`~/AuraHealth/ApplePromptTester/ios/ApplePromptTesterIOS.xcodeproj` and
wires in the Swift sources the skill scaffolds. Estimated time: ~3
minutes.

You only do this once per Mac. Subsequent skill invocations re-use the
project and don't need any Xcode UI interaction.

## Prerequisites

- Xcode 26+ installed from the App Store or developer.apple.com.
- Active toolchain pointed at it:
  `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
- An Apple Developer account signed in to Xcode → Settings → Accounts
  (free personal team works fine for device installs).
- An Apple Intelligence-capable iPhone (iPhone 15 Pro/Pro Max, or
  iPhone 16+) on iOS 26.x, paired via USB-C, trusted.

## Steps

1. **Scaffold the Swift sources** (the skill does this automatically on
   first run, or run it manually):

   ```bash
   ${CLAUDE_PLUGIN_ROOT}/skills/qa-apple-intelligence-prompt/scripts/scaffold_ios_sources.sh \
     "$HOME/AuraHealth/ApplePromptTester/ios"
   ```

   This drops two files:

   ```
   ~/AuraHealth/ApplePromptTester/ios/ApplePromptTesterIOS/
   ├── ApplePromptTesterIOSApp.swift
   └── ContentView.swift
   ```

2. **Create the Xcode project.** Open Xcode 26. File → New → Project →
   iOS → App. Settings:

   | Field | Value |
   |---|---|
   | Product Name | `ApplePromptTesterIOS` |
   | Team | Your Apple ID team (personal team is fine) |
   | Organization Identifier | something stable, e.g. `io.aurahealth` |
   | Interface | SwiftUI |
   | Language | Swift |
   | Storage | None |
   | Include Tests | unchecked |

   Click **Next**. When Xcode asks where to save, choose
   `~/AuraHealth/ApplePromptTester/ios` and **uncheck "Create Git
   repository"** (the dir is fine without one for this purpose).

3. **Set the deployment target to iOS 26.** Select the
   `ApplePromptTesterIOS` target → General → Minimum Deployments →
   iOS 26.0.

4. **Replace the autogenerated source files.** Xcode's "App" template
   creates `ApplePromptTesterIOSApp.swift` and `ContentView.swift`
   inside the project — delete both (move to trash, leaving
   references) and drag the two files from
   `~/AuraHealth/ApplePromptTester/ios/ApplePromptTesterIOS/` into the
   project navigator. When prompted, **uncheck "Copy items if needed"**
   so the project references the on-disk files the skill maintains.

5. **Confirm signing.** Target → Signing & Capabilities. Make sure
   "Automatically manage signing" is checked and a Team is selected.
   Bundle Identifier will be something like
   `io.aurahealth.ApplePromptTesterIOS` — write it down if you want to
   set it explicitly via the skill's `--bundle-id` flag, but the skill
   auto-derives it from `xcodebuild -showBuildSettings` so you usually
   don't need to.

6. **Build & run on device once, manually.** Plug in the phone, unlock,
   pick it from the device dropdown in Xcode, hit ⌘R. The first build
   provisions a development cert for the device and installs the app.
   Tap the running app in the simulator/device foreground so iOS knows
   the bundle has been launched at least once — that's what creates the
   app data container the skill writes `pending-run.json` into.

7. **Trust the developer cert on the phone** (only on personal teams).
   Settings → General → VPN & Device Management → tap your Apple ID →
   Trust.

You're done. Confirm by listing devices:

```bash
xcrun devicectl list devices
```

Your phone should appear as `available`. From here, the skill takes
over — re-invoke it and it'll build, install, push the pending run,
launch, fetch the results, and append a `## Run …` section to the
prompt-slug's `results.md`.

## Troubleshooting

- **"Could not find Developer Disk Image for iOS 26"** → update Xcode
  to a version that ships iOS 26 platform support. Xcode → Settings →
  Platforms → make sure iOS 26 is downloaded.
- **`xcodebuild` fails with "Signing for 'ApplePromptTesterIOS'
  requires a development team"** → step 5. The skill cannot inject a
  team on your behalf — it varies per developer.
- **`devicectl device copy to` fails with "container not found"** →
  step 6. The app needs to launch once before its data container
  exists on disk. The skill retries this automatically, but a manual
  first launch is the cleanest fix.
- **App launches but does nothing** → check that the two source files
  are actually in the target's "Compile Sources" build phase (target →
  Build Phases → Compile Sources). Sometimes Xcode references files
  without including them in the target.
